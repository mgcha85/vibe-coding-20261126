# AGENTS.md

프로젝트 특화(스택·데이터·포트·게이트 커맨드)는 PROJECT.md에 둔다. 모호하면 코딩 전에 역질문(Grill-me)한다.
절차·단계 실행은 .cursor/skills/가 SSOT다. CLAUDE.md는 만들지 않는다 (AGENTS와 중복).

Every-turn SSOT
## 1. 개별 프로젝트 6대 표준 문서 체계 & 역할
6 Standard Docs

모든 프로젝트 루트에는 다음 6대 마크다운 문서가 배치되어 에이전트의 드리프트(탈선)를 차단하고 작업 연속성을 보장합니다:

📁 project-root/
├── 🔗 AGENTS.md -> .knowledge/00_meta/AGENTS.md # 전역 헌법 링크
├── 📄 PROJECT.md # 프로젝트 고정 런타임/환경 명세
├── 📄 INTENT.md # 현재 스프린트 의도 & 바운더리
├── 📄 ROADMAP.md # 마일스톤 및 거시적 진행도
├── 📄 PLAN.md # 현재 작업 단위 세부 실행 계획서
├── 📄 ADR.md # 아키텍처 기술 결정 기록 (append-only)
└── 📄 LESSON_AND_LEARN.md # 누적 시행착오 & 트러블슈팅 장부
문서명 역할 및 성격 참조 시점 갱신 주기
PROJECT.md 런타임 환경, 포트, 스택, 불변 제약 세션 첫 턴, 인프라 작업 스택/포트/환경 변경 시에만
ROADMAP.md 거시적 마일스톤(M1~Mn), 일정, 진척도 세션 첫 턴, 스프린트 시작/종료 마일스톤 달성 및 변경 시
INTENT.md 현재 작업의 목적, 수용 기준, 제외 범위(Do NOT) 세션 첫 턴, 작업 착수(Grill-me) 새로운 기능/스프린트 시작 시
PLAN.md 구체적 파일 변경 명세([NEW]/[MODIFY]), 검증 계획 세션 첫 턴, 구현 코딩 직전 매 작업/스프린트 단위 승인 후
ADR.md 아키텍처·기술 스택 선정 결정 기록 (번호 증가) 세션 첫 턴, 아키텍처 설계 시 중요 기술/구조 결정 시 (Append-Only)
LESSON_AND_LEARN.md 재발 방지 장부 (증상, 원인, 해결책, 규칙) 세션 첫 턴, 디버깅/구현 착수 전 트러블슈팅/버그 해결 직후 (최신 상단)
## 2. 작업 착수 2대 필수 관문: Grill-me & PLAN.md Gate
승인 전 코딩 절대 금지

에이전트가 사용자의 첫 프롬프트를 수신했을 때, 코드 작성을 시작하기 전에 반드시 통과해야 하는 2단계 강제 게이트(Gate)입니다:

Gate 1: Grill-me 프로토콜 INTENT 100% 루프

원칙: 에이전트는 절대 사용자의 의도를 자의적으로 추측하거나 임의로 넘겨짚지 않는다.

  • 첫 프롬프트 수신 시 ./INTENT.md 필수 항목(Goal, Criteria, Scope) 충족도 자체 평가
  • 1%라도 모호함이 있다면 즉시 작업을 멈추고 날카로운 역질문(Grill-me, 3~5개) 투입
  • INTENT가 100% 명확해질 때까지 인터뷰 루프 지속
  • 합의된 내용을 ./INTENT.md에 기록 후 게이트 통과
Gate 2: Mandatory PLAN.md 프로토콜 승인 전 코딩 금지

원칙: 첫 프롬프트에서 코드를 바로 수정하거나 작성하는 것은 치명적 규정 위반이다.

  • INTENT 완성 후 코딩 전 반드시 ./PLAN.md 선작성
  • 스택, 상태 설계, 파일별 변경([NEW]/[MODIFY]), 단계별 로드맵, 검증 계획 명시
  • 작성 완료 시 실행을 중단(STOP)하고 사용자에게 명시적 검토/승인 요청
  • 사용자가 플랜을 승인하면 비로소 구현(Coding) 착수
## 3. 빈 세션 / 신규 쓰레드 첫 턴 문맥 적재 (Cold-Start Context Hydration)
7-Step Hydration

새로운 세션/쓰레드가 열렸을 때 AI 에이전트는 이전 대화 기억이 전혀 없는 상태(Stateless)입니다. 따라서 첫 턴에 질문에 답변하거나 코딩하기 전, 반드시 다음 7단계 순서로 프로젝트 문맥을 파악(Hydrate)한 후 작업에 착수합니다:

1
PROJECT.md 필독: 런타임 환경(스택, 빌드/기동 커맨드, 포트, 제약사항) 확인
2
ROADMAP.md 필독: 현재 좌표 확인(M1~Mn 마일스톤 중 위치와 남은 단계)
3
INTENT.md 필독: 현재 작업 목적(Why), 수용 기준(Do), 제외 범위(Do NOT) 확인
4
PLAN.md 필독: 직전/현재 진행 상황(실행 단계, 미완료 체크리스트) 확인
5
ADR.md 확인: 기술 결정 제약 확인(과거 기각/결정된 사항 번복·재질문 방지)
6
LESSON_AND_LEARN.md 확인: 지뢰밭 회피(과거 버그·실패 경험 학습하여 재발 차단)
7
관련 .cursor/skills/<name>/SKILL.md (필요 시 REFERENCE.md) 및 대상 모듈 소스 확인
## 4. 공통 코딩 및 운영 안전 규칙
  • 안전 제약: rm -rf, DROP TABLE / DROP DATABASE 파괴 명령은 명시 요청 없이 절대 금지
  • 시크릿 격리: .env 및 민감 API 키는 커밋 금지 (.gitignore 필수)
  • Git 제어: 커밋·푸시는 사용자 요청 시에만 수행
  • 품질 게이트: 프로젝트 품질 게이트 커맨드는 PROJECT.md를 따름
  • 사규 갱신: 새 스킬·규칙 생성 시 harness-agents-md로 동기화
## 5. 지식 환류 & 자산 승격 프로토콜
  • 프로젝트 로컬 기록: 해결된 버그, 예외 상황, 안티패턴을 ./LESSON_AND_LEARN.md 상단에 증상/원인/해결책/교훈 4줄 포맷으로 추가
  • 중앙 볼트 승격 (Graduation): 타 프로젝트에서도 쓰일 범용 자산은 .cursor/skills/ 신규 스킬로 승격하고 AGENTS.md 업데이트
  • 세션 복구 (Recovery): 세션 재개 시 항상 PLAN.md 미완료 체크리스트부터 이어받아 작업 중단 없이 연속 진행

## 8. 4대 Worktree 협업 규정 & Push 자동 머지
Multi-Agent Isolation
📁 main/ (시작점) 통합 허브, 공통 설정, 배포/CI, 에이전트 기본 작업 시작점
📁 ui/ 프론트엔드 (Svelte/Astro, ECharts, UI 컴포넌트)
📁 data/ DuckDB 스키마, 웨어하우스, ingest 파이프라인
📁 analytics/ 통계/ML 모델, 분석 파이프라인
  • 프로젝트 생성 및 신규 스프린트 시 항상 main/에서 시작한다.
  • 컨테이너 루트에는 코드를 직접 작성하지 않고 각 도메인 Worktree에서만 코딩한다.
  • 각 도메인 Worktree에서 작업 후 git push 시 pre-push 훅을 통해 main 브랜치로 자동 머지된다.
  • 머지 충돌 발생 시 main/으로 이동하여 충돌을 해결한 뒤 커밋한다.
💡 Tip: [마크다운 복사] 버튼을 눌러 프로젝트 루트의 AGENTS.md에 그대로 적용하십시오.
