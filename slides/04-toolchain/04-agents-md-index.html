# 1. 핵심 철학: 컨텍스트 낭비 없는 Tree 기반 탐색 (Zero-Blind Load)

- 원칙: 중앙 지식 베이스의 모든 문서를 한꺼번에 컨텍스트에 밀어 넣지 않는다.
- 계층 탐색: 각 폴더의 INDEX.md를 먼저 읽고, 필요한 도메인 가이드와 스킬 매뉴얼만 선택적으로 로딩하여 토큰 낭비를 원천 차단한다.

# 2. 작업 착수 2대 필수 관문: Grill-me & PLAN.md Gate

- Gate 1 (Grill-me 프로토콜): 사용자의 의도를 절대 자의적으로 넘겨짚지 않는다. 요구사항에 1%라도 모호함이 있다면 즉시 구체적 질문을 던져 INTENT.md(목적, 수용 기준, Out of Scope)를 100% 확정한다.
- Gate 2 (Mandatory PLAN.md): 첫 프롬프트에서 코드를 바로 작성하는 것은 치명적 규정 위반이다. 파일별 변경 명세([NEW]/[MODIFY]/[DELETE]) 및 검증 계획을 담은 PLAN.md를 작성하고, 사용자의 명시적 승인을 받은 후 코딩을 시작한다.

# 3. 공통 엔지니어링 & 거버넌스 수칙 (전역 표준 헌법)
1. 시크릿 격리: 중요 정보는 반드시 .env 사용 (.env.prod, .env.dev, .env.example 작성 및 .gitignore 추가).
2. 프론트엔드 표준: UI가 필요한 경우 Svelte + Tailwind CSS를 적극 사용하여 간결하고 모던하게 구현.
3. 백엔드 표준: 백엔드는 Rust로 통일 (Frontend: Svelte, Backend: Rust 단일 표준 체계).
4. DB & BaaS: 대용량 저장이 없으면 Supabase 우선 활용 (무료 Auth/DB/결제 연동 적극 채택).
5. 배포 제어: 기본 배포는 podman-compose, 실행/정지는 start.sh, stop.sh로 표준화.
6. 서버 직접 빌드 절대 금지: 원격 서버에서 cargo build 등 무거운 빌드 엄격 금지. GitHub Actions 러너에서 빌드 후 GHCR 푸시, 서버는 pull로만 배포.
7. Python 프로젝트: 반드시 uv sync로 패키지 및 버전을 관리.
8. AI 모델 표준: 기본 모델은 gemini-3.0-flash 사용, GOOGLE_API_KEY는 .env에 보관.
# 4. 세션 문맥 영속성 & 지식 환류 (Post-Task Hook)

- 트러블슈팅 장부: 버그나 예외 상황을 해결하면 즉시 LESSON_AND_LEARN.md 상단에 증상/원인/해결/교훈을 기록하여 동일 실수 재발을 영구 차단한다.
- 문서화 의무: docs/ 폴더에 API 규격과 아키텍처 문서를 유지하여 다른 개발자와 에이전트가 언제든 프로젝트 전체를 즉시 파악할 수 있도록 한다.
