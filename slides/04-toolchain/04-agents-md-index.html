# 1. Mission & Scope (PBMC 3k scRNA-seq Vibe Lab)

- Primary Goal: 10x Genomics PBMC 3k 데이터를 DuckDB 웨어하우스 → 분석 파이프라인 → Astro 대시보드 시각화까지 재현 가능한 연구 앱으로 구축.
- Scope: QC 필터링 → 차원축소/Leiden 군집 → Wilcoxon 마커 탐색 → 마커 기반 세포타입(T, B, Monocyte 등) 판정 → Astro 시각화.
- Out of Scope: 클라우드 다중 샘플 통합, 원시 데이터 재다운로드 금지(data/raw/pbmc3k_raw.h5ad에 이미 캐시됨).

# 2. Stack (강제 스택 & 엄격한 금기 사항)

- BE: Python 3.12 + .venv (uv로 패키지 관리)
- Warehouse SSOT: DuckDB (주력) — 테이블·집계·Astro 내보내기의 단일 진실 공급원
- DataFrame: Polars (보조) — SQL로 어색한 변환만 사용. import pandas 전면 금지
- Graph ML: scanpy / numpy / scipy / igraph (PCA, UMAP, Leiden 군집, rank_genes_groups만 허용)
- FE & Charts: Astro 5 + Apache ECharts 5 (echarts-setup.ts 기반; 손수 SVG나 타 차트 라이브러리 엄금)

# 3. Directory Ownership & Pipeline Order (절대 순서)

- 디렉토리 소유권:
  • data/raw/ : 읽기 전용 원본 h5ad (수정 금지)
  • data/warehouse/ : DuckDB 파일만 보관 (pbmc3k.duckdb)
  • backend/ : 파이프라인 단계 모듈 / frontend/ : Astro 앱 (시각화 SSOT)
- 파이프라인 절대 순서:
  1. db-ingest-h5ad ➔ 2. data-analytics-eda ➔ 3. data-analytics-qc ➔ 4. data-analytics-dimreduce-cluster ➔ 5. data-analytics-markers ➔ 6. data-analytics-celltype ➔ 7. data-analytics-export
  ※ 앞 단계 산출물 없이 뒷 단계를 구현하지 않는다!

# 4. Quality Gates & Safe Change Policy

- 3대 품질 검증 게이트:
  1) .venv/bin/python -c "import pandas" ➔ 반드시 ImportError 발생 확인
  2) .venv/bin/ruff check backend/ ➔ 린트 무결성 검증
  3) cd frontend && npm run build ➔ Astro 정적 빌드 100% 성공
- 안전 규칙: 커밋은 사용자 요청 시에만 수행, DROP TABLE 및 원본 삭제 금지, 트러블슈팅 발생 시 LESSON_AND_LEARN.md 기록 의무.

💡 모든 AI 에이전트는 작업 시작 전 위 헌법을 읽고 절대 벗어나지 않습니다.
