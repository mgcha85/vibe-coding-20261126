# AGENTS.md

프로젝트 특화(스택·데이터·포트·게이트 커맨드)는 PROJECT.md에 둔다. 모호하면 코딩 전에 역질문한다.

SSOT Constitution
## 0) 문서 역할
문서 역할
AGENTS.md 공통 규칙, 컨텍스트 로드, 스킬 인덱스 (본 문서)
INTENT.md 왜 / 누구 / 수락 기준 / 비목표 (Scope & Acceptance Criteria)
PLAN.md 세션 체크리스트 · 진행 상태 ([NEW]/[MODIFY]/[DELETE])
PROJECT.md 미션 · 기술 스택 · 경로 · 파이프라인 · 데이터 계약 · 품질 게이트
LESSON_AND_LEARN.md 시행착오 및 재발 방지 장부 (증상 / 원인 / 해결 / 교훈 4줄 포맷)
ADR.md / ROADMAP.md 있으면 아키텍처 결정 · 로드맵 (없으면 억지로 만들지 않음)

👉 절차 · 단계 실행은 .cursor/skills/가 SSOT다. CLAUDE.md는 만들지 않는다 (AGENTS와 중복).

## 1) Context Load Order (코드 수정 전 엄격 로딩 순서)
1단계 AGENTS.md 공통 헌법 확인
2단계 INTENT ➔ PLAN ➔ PROJECT 범위 · 계획 · 스택
3단계 .cursor/skills/*/SKILL.md 필요시 REFERENCE.md
4단계 LESSON_AND_LEARN.md 과거 실수 사전 차단
5단계 대상 모듈 소스 최종 수정 작업
## 2) 공통 코딩 / 운영 규칙
  • 요구가 모호하면 구현하지 말고 Grill-me한다.
  • 커밋 · 푸시는 사용자 요청 시에만 수행한다.
  • .env 및 시크릿을 절대 커밋하지 않는다.
  • rm -rf, DROP TABLE / DROP DATABASE 등 파괴 명령은 명시 요청 없이 금지.
  • 프로젝트 품질 게이트 커맨드는 PROJECT.md를 따른다.
  • 새 스킬 · 에이전트 · 운영 규칙이 생기면 harness-agents-md 기준으로 본 문서를 갱신한다.
## 3) Grill-me

구현 전 3~5개만 묻는다.
예: 어느 파이프라인/모듈 단계인지, 어느 경로·산출물을 건드리는지, 새 라우트/테이블/문서인지, 범위 밖 요청인지.
