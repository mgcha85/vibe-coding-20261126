모든 프로젝트에 똑같은 룰을 복붙하면 유지보수가 불가능해집니다. 전사 공통 스킬과 도메인 특화 규칙을 깔끔히 분리해야 합니다.

🌐 전사 공통 모듈 (Global / Cross-Project)
Symlink · Submodule

회사나 팀의 모든 레포지토리에서 100% 동일하게 공유되는 표준 거버넌스 문서와 범용 스킬 팩입니다.

📜 AGENTS.md (공통 헌법) 루트 심볼릭 링크
• .env 시크릿 관리, 배포 게이트, 커밋 컨벤션, 공통 파괴적 명령어 금지 룰.
• 중앙 사규 저장소(harness-collection)에서 Git Submodule/심볼릭 링크로 연결.
📂 skills/ (공통 스킬 팩) 범용 자동화
• uiux-governance: 사내 공통 디자인 시스템/Tailwind 색상 토큰.
• deployment-operations: podman-compose, CI/CD 공통 파이프라인.
💡 중앙 집중식 장점: 사내 코딩 컨벤션이나 보안 가이드가 바뀌면 중앙 레포 수정 하나로 모든 프로젝트에 즉시 동기화!

## Pipeline Order (절대 순서)
  1. db-ingest-h5ad — h5ad ➔ DuckDB
  2. data-analytics-eda — 기본 EDA + ui-viz-eda (/eda)
  3. data-analytics-qc — QC 필터 + ui-viz-qc
  4. data-analytics-dimreduce-cluster — PCA/UMAP/Leiden + ui-viz-umap
  5. data-analytics-markers — DEG + ui-viz-dotplot / ui-viz-violin
  6. data-analytics-celltype — 마커 기반 타입 추론
  7. data-analytics-export — Astro용 아티팩트 갱신

👉 앞 단계 산출물 없이 뒷 단계를 구현하지 않는다. 오케스트레이션: ops-pipeline-orchestration.

## Runtime & Dependency Policy
• Python: .venv (CPython 3.12), 패키지 관리: uv
• Frontend: Astro 5 (frontend/, pin astro@5.16.6; Node 22.22 OK)
• Warehouse: data/warehouse/pbmc3k.duckdb
• Allowed BE: duckdb, polars, scanpy, anndata, numpy, scipy, scikit-learn, igraph, umap-learn, h5py, pyarrow, ruff
• FE Charts: Apache ECharts 5 (echarts). 차트 색은 ui-design-tokens CSS 변수만 허용.
## Data Contract & Seed Data
• 원본: data/raw/pbmc3k_raw.h5ad (2700 × 32738, raw count, hg19)
• 스키마: 스킬 db-duckdb-schema
• 분석 시드: 난수 고정 random_state=0 / sc.settings.seed = 0
• QC 기본 필터: pct_counts_mt < 5 AND 200 <= n_genes_by_counts < 2500
• Local UI: http://127.0.0.1:8899 (Footer Brand: ChaLab)
## Analysis defaults 
seed = 0
mt gene prefix = MT-
keep cells: pct_counts_mt < 5 AND 200 <= n_genes_by_counts < 2500
filter_genes min_cells = 3
