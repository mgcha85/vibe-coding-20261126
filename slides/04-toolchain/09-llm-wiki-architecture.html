Chapter 04. 툴체인 · 4.8 중앙 집중형 LLM-Wiki MULTI-DEPTH · 3-TIER MEMORY REFINEMENT

중앙 집중형 LLM-Wiki : 3계층 정제 & Multi-Depth 아키텍처

단순 폴더 트리 구조가 아닙니다. Raw(원천 자료) ➔ Schema(정제 규칙) ➔ Wiki(영속적 개념/결정/스킬)로 지식을 컴파일하여 전 프로젝트가 공유하는 고차원 인지 시스템입니다.

⚙️ LLM-Wiki 3계층 컴파일 파이프라인 RAG 초월 지속 축적
📥 Layer 1. Raw Sources (불변 원본) Immutable
/raw/ 논문, 거래소 API 문서, 회의록, 장애 로그 (AI 읽기 전용)
↓ 🤖 AI 정제 & 지식 인제스트 (Ingest / Lint) ↓
📜 Layer 2. Schema (정제 헌법) Rule of Law
AGENTS.md · 템플릿(entity, decision) ➔ AI에게 위키 작성 규칙 강제
↓
🧠 Layer 3. The Compounding Wiki Persistent SSOT
AI가 자동 상호참조(Cross-reference)하고 갱신하는 살아있는 지식 베이스.
🌐 Hub-and-Spoke 공유 연결 전 프로젝트 심볼릭 링크
Project A (Web)
Project B (Go)
Project C (AI)
💡 RAG는 매번 제로베이스 검색하지만, LLM-Wiki는 지식이 누적 컴파일됩니다.
📂 실전 Multi-Depth 위키 디렉토리 구조 harness-collection 실체

스킬이 비대해져 생기는 상충(Conflict)과 토큰 낭비를 막기 위해, 위키는 인덱스 · 엔티티 · 의사결정 · 원자 스킬로 다층 분할(Multi-Depth)됩니다.

📁 harness-collection/ (중앙 집중형 LLM-Wiki)
├── 📜 AGENTS.md (최상위 공통 헌법 · 보안 · 배포 계약)
├── 📑 LESSON_AND_LEARN.md (전사 공통 오답노트 · 자가 치유)
├── 📂 wiki/ (지식 베이스 코어)
├── 📑 index.md ➔ 위키 전체 카탈로그 (양방향 링크 [[...]] 인덱싱)
├── 📁 entities/ ➔ 핵심 개념 · 패턴 ([[backtesting-rules]], [[data-contract]])
├── 📁 decisions/ ➔ 아키텍처 결정 · 시행착오 ([[look-ahead-bias-fix]])
└── 📁 _templates/ ➔ 새 지식 인제스트용 표준 양식 (entity, decision)
└── 📂 .cursor/skills/ (상충 제거를 위해 원자 단위로 잘게 쪼갠 스킬 팩)
├── 📁 ui-components/ · 📁 ui-tailwind/ (UI 그룹)
├── 📁 ops-deployment/ · 📁 ops-podman/ (인프라 그룹)
└── 📁 trading-db-schema/ · 📁 wiki-management/ (도메인/위키관리)
⚠️ 스킬이 비대할 때 (Monolithic): 문서 길이 폭증 ➔ 규칙 상충(Tailwind 충돌 등) ➔ AI 지시 망각 및 환각.
✅ 위키 Multi-Depth 분할 (Atomic): index.md로 필요한 페이지만 열람 ➔ 상충 원천 차단 ➔ 토큰 절감 극대화.
🎯 위키 관리 스킬(wiki-management): 새 자료가 오면 AI가 스스로 위키 문서를 작성하고 index.md에 링크를 거는 자율 루프 가동.
🧠 LLM-Wiki 완성형: Raw ➔ Schema ➔ Wiki(Entities/Decisions) 3계층과 원자 단위 Skills 분할로 상충 없는 영구 지식을 구축하십시오.
