문서 설계학 : SKILL.md vs REFERENCE.md 분리

모든 규칙을 하나의 파일에 다 넣으면 토큰이 폭발하고 인지 부하가 생깁니다. 1단계 경량 실행 규칙과 2단계 심층 레퍼런스로 계층화해야 합니다.

📄 Level 1 : SKILL.md (실행 헌법 & 트리거)
Always Loaded on Trigger

에이전트가 스킬을 감지하는 순간 즉각 컨텍스트에 로드되는 핵심 강령입니다. 50~100줄 이내로 핵심 요약과 강제 사규만 기술합니다.

---
name: ui-tailwind-design
description: "Svelte 및 Tailwind CSS 컴포넌트 작성 시 16:9 다크 테마와 반응형 Bento 그리드를 강제 적용한다"
---
# 1. 디자인 강제 원칙 (Strict Rules)
- 배경은 항상 bg-slate-950 및 반투명 Bento 카드
- 복잡한 컴포넌트 작성 시 반드시 REFERENCE.md를 읽고 시작할 것.
# 2. 금지 사항 (Hard Guardrail)
- 인라인 스타일 작성 금지, 16:9 비율 왜곡 금지
✓ YAML Frontmatter 필수: name과 description이 에이전트의 트리거 지표
✓ 초경량 유지: 토큰 낭비를 막고 에이전트의 핵심 작업 지침만 전달
⚡ 역할: 에이전트가 "내가 지금 무엇을 지켜야 하는지" 즉각 행동 방향을 잡는 스위치
📑 Level 2 : REFERENCE.md (온디맨드 심층 문서)
On-demand Reading Only

수백 줄의 API 명세, 색상표, 복잡한 DB 스키마, 체크리스트를 담는 외장 참고 도서관입니다. 에이전트가 view_file로 직접 열람합니다.

📑 REFERENCE.md / CHEATSHEET.md 디자인 토큰 · 팔레트
Tailwind 색상 코드 Hex 매핑(#0f172a, #38bdf8), 폰트 스케일, 세부 아이콘 SVG 코드 보관.
📋 CHECKLIST.md / ALGORITHM.md 단계별 검증표
배포 전 필수 점검 항목 20가지, RLS 보안 감사 체크리스트, 예외 케이스 처리 매뉴얼.
🗄️ SCHEMA.md / API_CONTRACT.md 스키마 명세서
수십 개 테이블의 PostgreSQL 컬럼 명세, 바이낸스 선물 WebSocket 메시지 규격.
💡 경제학: 매 턴 읽으면 수만 토큰 낭비 ➔ 에이전트가 "필요할 때만 파일 읽기 도구"로 선택적 열람
📚 문서 2단계 분리 원칙: SKILL.md로 경량 라우팅하고, 대용량 지식은 REFERENCE.md로 외주화하여 토큰을 절약하십시오.
