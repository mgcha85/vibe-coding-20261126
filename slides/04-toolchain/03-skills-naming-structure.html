Skills 디렉토리 구조 & 네이밍 규칙의 미학

스킬은 단순한 메모장이 아닙니다. 에이전트가 사용자의 작업 의도(Intent)를 감지하고 스스로 도구를 꺼내 들게 만드는 의도 기반 라우팅 시스템입니다.

📂 표준 스킬 디렉토리 트리 .cursor/skills/
📁 my-project/
├── 📜 AGENTS.md (매 턴 인덱스/헌법)
├── 📂 .cursor/skills/ (또는 .agents/skills)
├── 📁 ui-components/ (프론트엔드 그룹)
│ ├── 📄 SKILL.md (트리거 메타데이터 + 사규)
│ └── 📑 REFERENCE.md (필요시 읽는 디자인 가이드)
├── 📁 ui-tailwind-design/
│ └── 📄 SKILL.md
├── 📁 trading-db-schema/ (백엔드/도메인 그룹)
│ ├── 📄 SKILL.md
│ └── 📑 INDEX.md
└── 📁 ops-deployment/ (인프라/운영 그룹)
└── 📄 SKILL.md
💡 심볼릭 링크 팁: .cursor/skills ↔ .opencode/skills ↔ .agents/skills 로 연결하면 어떤 툴에서도 단일 스킬 팩이 그대로 작동합니다.
🏷️ Naming Prefix가 에이전트 라우팅을 좌우한다 Trigger Optimization

에이전트는 사용자의 프롬프트에서 키워드를 파싱하여 매칭되는 스킬을 선택합니다. 폴더 이름과 스킬 이름에 명확한 도메인 접두사(Prefix)를 붙여야 에이전트가 혼란 없이 단번에 해당 스킬을 인지합니다.

ui-* 프론트엔드 및 시각 디자인 그룹 Trigger: 버튼, 레이아웃, 모달, CSS
ui-components, ui-tailwind-design, uiux-governance
→ UI 요청 시 백엔드 린터나 DB 스키마가 끼어들지 않고 UI 디자인 사규만 깔끔하게 활성화.
ops-* 인프라, CI/CD & 배포 운영 그룹 Trigger: 배포, 포드맨, 깃허브 액션, 포트
ops-deployment, ops-podman-compose, ops-secrets-audit
→ 배포 명령어 입력 시 포트 충돌 체크, .env.prod 보안 검증 룰이 자동으로 가동.
domain-* 핵심 비즈니스 & 데이터 파이프라인 그룹 Trigger: 백테스트, 지표, 모델, 거래체결
trading-db-schema, btc-backtest-workflow, prompt-drift-prevention
→ 금융 데이터 계약(/mnt/data/finance)과 지표 표준을 즉각 에이전트에 주입.
✓ 네이밍 핵심: "에이전트가 프롬프트 단어 하나만 보고도 즉시 폴더를 찾을 수 있도록 접두사를 구조화하라"
📂 구조적 스킬 설계: 디렉토리 구조와 ui-* 프리픽스는 단순 정리가 아니라 AI 인지 라우팅의 핵심 지도입니다.
