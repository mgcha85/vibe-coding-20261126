## [Issue #24] 장 초반 09:00 주식 호가 수신 중 WebSocket 403 에러 발생
• 증상 (Symptom): 장 시작 09:00 동시호가 급증 시 증권사 실시간 웹소켓 세션이 끊기고 403 Forbidden 에러 반복.
• 원인 분석 (Root Cause): 한국투자증권(KIS) OAuth2 액세스 토큰의 유효기간(24시간) 만료 시 자동 재발급 메커니즘 부재 및 만료 시점에 다중 고루틴이 동시 재발급을 요청하면서 Rate Limit 초과.
• 근본 해결책 (Fix):
1) Go 엔진 내 TokenManager 싱글톤 구현: 만료 15분 전 백그라운드 선제 갱신
2) sync.RWMutex를 적용하여 갱신 중 들어오는 웹소켓 요청을 안전하게 대기 큐잉
• 검증 (Verification): 토큰 만료 가상 주입 테스트(go test -v -run TestTokenAutoRefresh) 100% 통과 확인.
• 교훈 (Rule for Agent): "인증 토큰 기반 실시간 스트리밍은 단순 만료 후 재시도가 아닌, 사전 백그라운드 갱신과 동시성 Lock을 필수로 설계할 것."

# INTENT.md · 핵심 제품 철학 & 비기능적 요구사항 (Intent SSoT) Design Intent

"왜 시스템이 이렇게 만들어졌는가"를 정의하여, 에이전트가 리팩토링 중 핵심 철학을 임의로 훼손하거나 불필요한 복잡성을 도입하는 것을 차단합니다.

## 1. 근본 설계 철학 (Core Design Invariants)
• Zero-External DB Dependency: 중앙 집중형 무거운 DB 대신 SQLite + Parquet 조합을 고수하여 단일 바이너리 엣지 구동 지원.
• Strict Separation of Brain & Muscle: Python(연구/전략 연산)과 Go(실시간 체결/네트워크 I/O)의 역할을 절대 단일 언어로 합치지 않는다.
## 2. 금기 사항 (Anti-Patterns / Forbidden Actions)
• 하드코딩 금지: 전략 수식이나 손절 수치를 Go 엔진 소스에 직접 쓰지 말고 항상 config/strategy_params.json을 통해 주입할 것.
• 모의검증 없는 실주문 엄금: 단위 테스트와 백테스트 3개년 슬리피지 검증 전에는 실계좌 주문 루틴을 활성화하지 말 것 (DRY_RUN=true 유지).
# ADR.md · Architectural Decision Records (아키텍처 의사결정 기록) Architectural SSoT

주요 기술적 선택의 배경, 대안 평가, 채택 이유와 결과를 공식 문서로 박제하여 미래의 개발자와 에이전트가 뒤엎지 못하게 합니다.

## ADR-007: 실시간 틱 데이터 스토리지로 SQLite WAL 모드 채택
Status: Accepted · Date: 2026-03-15
• Context (문제 상황): 초당 수천 건의 주식 틱 데이터와 5단계 호가 잔량을 로컬에 초저지연 영속화해야 함. Redis나 PostgreSQL 데몬을 띄우면 메모리 오버헤드와 배포 복잡도 급증.
• Decision (결정 사항): Go 내장 임베디드 SQLite에 PRAGMA journal_mode=WAL 및 PRAGMA synchronous=NORMAL 적용.
• Consequences (결과 및 트레이드오프):
- 장점: 단일 노드에서 초당 35,000건 삽입 처리 달성, 추가 인프라 데몬 0개, 단일 파일 복사로 백업 완료.
- 제약: 동시 쓰기는 싱글 스레드로 제한되므로 Go 채널 기반 단일 워커 큐 패턴 준수 필수.
💡 세션이 끊겨도 이 5대 문서를 읽은 에이전트는 0초 만에 이전 맥락을 100% 복원합니다.
💾 영속성 삼각편대: LESSON(오답노트) + PLAN(체크리스트) + INTENT(설계의도)가 세션 변경 시 컨텍스트를 100% 지킵니다.
