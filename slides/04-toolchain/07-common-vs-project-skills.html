Chapter 04. 툴체인 · 4.6 스킬 계층 분리 COMMON SKILLS · PROJECT SPECIALIZATION

공통 모듈과 프로젝트 특화 : AGENTS.md vs PROJECT.md

모든 프로젝트에 똑같은 룰을 복붙하면 유지보수가 불가능해집니다. 전사 공통 스킬과 도메인 특화 규칙을 깔끔히 분리해야 합니다.

🌐 전사 공통 모듈 (Global / Cross-Project)
Symlink · Submodule

회사나 팀의 모든 레포지토리에서 100% 동일하게 공유되는 표준 거버넌스 문서와 범용 스킬 팩입니다.

📜 AGENTS.md (공통 헌법) 루트 심볼릭 링크
• .env 시크릿 관리, 배포 게이트, 커밋 컨벤션, 공통 파괴적 명령어 금지 룰.
• 중앙 사규 저장소(harness-collection)에서 Git Submodule/심볼릭 링크로 연결.
📂 skills/ (공통 스킬 팩) 범용 자동화
• uiux-governance: 사내 공통 디자인 시스템/Tailwind 색상 토큰.
• deployment-operations: podman-compose, CI/CD 공통 파이프라인.
💡 중앙 집중식 장점: 사내 코딩 컨벤션이나 보안 가이드가 바뀌면 중앙 레포 수정 하나로 모든 프로젝트에 즉시 동기화!
🎯 프로젝트 특화 모듈 (Project-Specific)
Local Repository Only

해당 레포지토리 고유의 비즈니스 도메인, 데이터 스키마, 특화 파이프라인만 격리하여 기술하는 전용 문서입니다.

📋 PROJECT.md (프로젝트 특화 정의서) 🔍 클릭: 예시 보기
• 현재 시스템의 비즈니스 목표: "미국 대형 기술주 & KOSPI 1m/5m VWAP 모멘텀 돌파 전략"
• 이 프로젝트만의 데이터 계약: /data/stock_market, 증권사 실시간 Open API 명세.
📂 skills/domain-* (도메인 특화 스킬) 해당 레포 한정
• stock-db-schema: 주식 일봉/분봉 틱 데이터 및 수정주가 보정 SQLite DDL.
• stock-backtest-live-workflow: 퀀트 백테스트 검증 결과를 Go 실시간 주문 집행 엔진으로 연계.
💡 도메인 격리 원칙: 공통 사규(AGENTS.md)를 더럽히지 않고, 각 프로젝트의 특수성을 독립적으로 보존!
📋 PROJECT.md · 미국 대형 기술주 & KOSPI 주식 퀀트 실전 정의서 (Domain SSOT) 주식 도메인 특화
# 1. Project Mission & Equity Strategy Scope

- Primary Goal: 미국 S&P500/나스닥100 대형 기술주 및 KOSPI200 주도주 대상 실시간 퀀트 알고리즘 트레이딩 파이프라인.
- Core Strategy: 1분봉/5분봉 가격 모멘텀 돌파 + 거래량 가중 평균가(VWAP) 밴드 회귀 하이브리드 전략.
- Execution Stack Split:
  • Research & Backtest: Python 3.12 (Polars 벡터 연산, 파라미터 그리드 탐색, 슬리피지/수수료 시뮬레이션)
  • Live Trading Engine: Go 1.23 (초저지연 실시간 시세 파싱, 호가 잔량 불균형 감시, 주문 집행 엔진)
  • Monitoring Frontend: Svelte + Tailwind CSS (실시간 체결 및 포지션 PnL 대시보드)

# 2. Equity Data Contract & Hive Partition

- Market Data Root: /data/stock_market (절대경로 엄수; 임의 변경 금지)
- Partition Layout: /data/stock_market/ticks/market={US|KR}/symbol={TICKER}/dt=YYYY-MM-DD/
- Corporate Actions Invariant: 주식 액면분할, 무상증자, 배당락 이벤트 시 수정주가(Adjusted Close) 계산 모듈을 거쳐 백테스트 데이터 정합성 보장.
- Broker API: 국내 주식 한국투자증권(KIS) Open API + 해외 주식 Interactive Brokers(IBKR) REST/WebSocket 연동

# 3. Risk Management & Circuit Breakers

- 포지션 사이징: 단일 주식 종목당 전체 운용 자산의 최대 10% 이내 엄수.
- 손절 및 익절 규칙: 진입가 대비 -1.8% 도달 시 즉시 시장가 손절(Stop-Loss), +3.5% 도달 시 50% 분할 익절 후 트레일링 스탑 활성화.
- 일간 최대 손실 제한(Daily MDD): 당일 누적 손실 -3.0% 도달 시 전 포지션 즉시 시장가 청산 및 당일 신규 진입 전면 중단(Circuit Breaker).
- 체결 슬리피지 통제: 매수/매도 5단계 호가 잔량 비율(Order Book Imbalance)이 1.5배 이상 유리할 때만 주문 제출.

# 4. Backtest-to-Live Handoff Protocol

- 배포 승인 기준: 최근 3년(2023~2026) 백테스트 결과 샤프비율 > 1.8, 승률 > 54%, 거래당 기댓값(왕복 0.1% 수수료/슬리피지 차감 후) 양수 보장.
- 전략 파라미터 고정: Python 연구 단계에서 검증된 파라미터는 config/strategy_params.json으로 추출되어 Go 엔진 런타임에 주입.
- 텔레그램 체결 알림: 주문 생성, 정정, 체결(`open -> close`) 발생 시 텔레그램 봇으로 실시간 손익 및 슬리피지 보고 전송.

💡 공통 헌법(AGENTS.md) 아래에 각 도메인의 핵심 비즈니스 규칙(PROJECT.md)이 완벽히 독립 보존됩니다.
🏛️ 2원화 설계: AGENTS.md로 회사의 공통 뼈대를 세우고, PROJECT.md로 도메인의 살을 붙이십시오.
