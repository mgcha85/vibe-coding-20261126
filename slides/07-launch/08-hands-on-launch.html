Chapter 07. 런칭 · 7.7 실전 5분 핸즈온 HANDS-ON · 3-STEP LAUNCH

실전 5분 실습 : 0원에서 상용 런칭까지

BaaS 인증, 결제 위젯, CI/CD 자동 배포 파이프라인을 3단계로 연결하여 실제 인터넷에 살아있는 서비스를 런칭합니다.

STEP 1. SNS 인증 연동 소요 시간 2분

Supabase Auth · RLS

대시보드에서 SNS 프로바이더를 켜고 환경변수를 로컬과 Vercel에 주입합니다.

# 1. .env.dev 환경변수 등록
VITE_SUPABASE_URL="https://xxx.supabase.co"
VITE_SUPABASE_ANON_KEY="eyJhbGciOi..."
# 2. 프론트엔드 로그인 호출:
await supabase.auth.signInWithOAuth({
provider: 'google', redirectTo: callbackUrl
});
# 3. PostgreSQL RLS 보안 활성화:
ALTER TABLE profiles ENABLE ROW LEVEL SECURITY;
CREATE POLICY p1 ON profiles FOR ALL USING (auth.uid() = id);
✅ Step 1 검증:
[x] 구글 로그인 시 auth.users 행 자동 생성
[x] RLS 정책으로 타인 데이터 접근 100% 거절
✓ 1클릭으로 Google OAuth 인증 흐름 완성
STEP 2. Toss 결제창 · Footer 소요 시간 2분

결제 위젯 · 필수 약관

토스페이먼츠 테스트 클라이언트 키를 연결하고 법적 필수 표기사항을 푸터에 배치합니다.

# 1. Toss 결제 위젯 렌더링 & 요청:
const widget = loadPaymentWidget(clientKey, customerKey);
widget.renderPaymentMethods('#payment-methods', 29000);
widget.requestPayment({ orderId, orderName: 'PRO 요금제' });
# 2. 백엔드 결제 승인 API:
POST https://api.tosspayments.com/v1/payments/confirm
headers: { Authorization: `Basic ${secretKeyBase64}` }
⚖️ 3. Footer 필수 법적 고지 4요소:
• 약관: 이용약관, 개인정보처리방침, 환불/취소 정책
• 사업자: 상호명, 대표자명, 등록번호, 통신판매번호
✅ Step 2 검증:
[x] 테스트 카드로 1,000원 결제 승인 200 OK
[x] PG 심사 필수 약관 링크 푸터 노출 확인
✓ PG사 심사 기준을 즉시 충족하는 결제창 완성
STEP 3. GitHub Actions 배포 소요 시간 1분

Git Push ➔ 라이브 서빙

GitHub Repository Settings에 시크릿을 등록하고 push하여 자동 배포를 확인합니다.

# 1. GitHub Secrets 등록:
DEPLOY_HOST: "203.0.113.10"
DEPLOY_SSH_KEY: "-----BEGIN OPENSSH PRIVATE KEY..."
DEPLOY_USER: "ubuntu"
# 2. .github/workflows/deploy.yml:
on: { push: { branches: [ 'main' ] } }
script: "cd /app && git pull && ./start.sh prod"
# 3. 터미널 푸시 즉시 배포 트리거:
$ git add . && git commit -m "launch"
$ git push origin main
✅ Step 3 검증:
[x] GitHub Actions 워크플로우 통과 (✓ 녹색)
[x] 운영 서버 라이브 도메인 200 OK 접속 확인
✓ 손 하나 대지 않고 프로덕션 무중단 릴리즈 완료
💡 실습 핵심: 로컬 터미널에서 서버에 직접 접속하지 마십시오. 모든 인프라 변경과 배포는 Git Commit과 GitHub Actions를 통해서만 실행되어야 안전합니다.
