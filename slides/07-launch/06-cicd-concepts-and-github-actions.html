Chapter 07. 런칭 · 7.5 배포 자동화 파이프라인 CONTINUOUS INTEGRATION · CONTINUOUS DEPLOYMENT

CI/CD의 본질 & GitHub Actions 자동 배포

"내 컴퓨터에서는 잘 도는데?"를 영원히 없앱니다. Git push 한 번으로 검증(CI) ➔ 빌드 ➔ 무중단 배포(CD)가 끝나는 자동화 게이트를 구축합니다.

❌ 수동 배포의 비극 vs CI/CD
사람의 실수 차단
⚠️ 로컬 수동 배포(FTP/SSH 직접 복사)의 위험 빌드 산출물 누락, 로컬 환경 의존성 오염, 배포 중 서버 다운타임, 시크릿 키 유출 위험 상존.
🔍 CI (지속적 통합 - Continuous Integration) 푸시 즉시 클라우드 격리 환경에서 린트(Ruff/ESLint), 타입 검사, 유닛 테스트를 자동 통과해야만 브랜치 병합 허용.
🚀 CD (지속적 배포 - Continuous Deployment) CI 검증이 통과된 클린 코드만 운영 서버(Cloud Run, VM, Vercel)에 무중단 자동 릴리즈.
🔄 CI/CD 4단계 상태 전이 게이트:
[1. Push] Git commit ➔ GitHub 원격 저장소
[2. CI Gate] Ruff & Pytest ➔ 실패 시 배포 중단!
[3. Build] 컨테이너 빌드 & GHCR 이미지 태깅
[4. CD Live] SSH 무중단 재기동 (./start.sh prod)
✓ "인간은 코드를 푸시하고, 배포는 기계가 수행한다" Zero Human Error
⚙️ 실전 GitHub Actions : .github/workflows/deploy.yml
월 2,000분 무료 러너
name: Production Deploy
on: { push: { branches: [ 'main' ] } }
jobs:
ci-test: # 1단계: 품질 검증
runs-on: ubuntu-latest
steps:
- uses: actions/checkout@v4
- run: uv run ruff check && uv run pytest -q
cd-deploy: # 2단계: 테스트 통과 시에만 배포
needs: ci-test
runs-on: ubuntu-latest
steps:
- uses: appleboy/ssh-action@v1.0.3
with:
host: ${{ secrets.DEPLOY_HOST }}, key: ${{ secrets.DEPLOY_SSH_KEY }}
script: "cd /app && git pull && ./start.sh prod"
🔐 GitHub Secrets & SSH Key 발급 가이드:
$ ssh-keygen -t ed25519 -C "deploy_runner" -f ~/.ssh/deploy_key
GitHub Settings > Secrets: DEPLOY_HOST, DEPLOY_SSH_KEY, DEPLOY_USER
✓ GitHub Repository Secrets를 활용해 비밀번호·SSH 키 완벽 은폐 Secret Safe
💡 실무 원칙: 배포 서버 접속 권한은 개인 비밀번호가 아닌 SSH 개인키를 GitHub Secrets에 등록하여 CI 러너만 접근하도록 엄격히 제한하십시오.
