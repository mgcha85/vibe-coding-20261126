Chapter 07. 런칭 · 7.3 클라우드 인프라 아키텍처 비교 VERCEL vs CLOUD RUN vs CLOUD VM

배포 환경 3대 패러다임 : Vercel · Cloud Run · VM

"어디에 올려야 하는가?" — 프론트엔드 특화 PaaS, 서버리스 컨테이너, 전통적 가상 서버(IaaS)의 작동 원리와 차이점을 비교합니다.

1. Vercel (Edge PaaS) 프론트엔드 0-Ops

Next.js · Svelte 최적화

Git 푸시 즉시 글로벌 엣지 CDN에 배포되며 브랜치별 프리뷰 URL 자동 생성.

Git Push ➔ Edge Build ➔ 300+ 글로벌 CDN PoP ➔ TTFB < 20ms
장점: 인프라 설정 0초, 빠른 CDN 응답, Git 연동 자동화
한계: 15~60초 타임아웃, WebSocket 지속 연결 불가
비용 (0트래픽): $0 (취미 플랜 평생 무료)
💻 $ npx vercel --prod (10초 배포)
🎯 적합: 웹 프론트, 블로그, 포트폴리오, 가벼운 API
2. GCP Cloud Run (Container) Scale-to-Zero

서버리스 컨테이너

Dockerfile만 있으면 Go, Python, Rust 등 어떤 언어든 HTTP 요청 단위로 기동.

Dockerfile ➔ Scale-to-Zero ($0) ➔ Request ➔ 1초 확장 (0➔1000)
장점: 트래픽 0이면 0원, 트래픽 폭증 시 무제한 자동 스케일링
한계: 첫 요청 시 콜드 스타트(1~2초), 60분 최대 타임아웃
비용 (0트래픽): $0 (월 200만 건 완전 무료)
💻 $ gcloud run deploy api --image gcr.io/app
🎯 적합: Go/Python 백엔드 API, AI 추론 서빙, 비정기 배치
3. Cloud VM / VPS (IaaS) 24/7 상시 가동

AWS EC2 · GCP · Hetzner

전용 CPU/메모리를 점유하는 완전한 가상 머신. Podman/Docker Compose로 운영.

Dedicated OS ➔ Podman / Compose ➔ Systemd ➔ 24/7 연결 유지
장점: WebSocket 무제한 지속, 24시간 백그라운드 봇, 고정 비용
한계: OS 보안 패치, Nginx 리버스 프록시, 수동 관리(Ops) 필요
비용 (0트래픽): 월 $4~10 (고정 요금제)
💻 $ podman-compose up -d && ./start.sh prod
🎯 적합: 24시간 트레이딩 봇, 웹소켓 거래소, 대용량 캐시/DB
💡 아키텍처 공식: 프론트는 Vercel, 간헐적 API는 GCP Cloud Run, 24시간 실시간 데몬/봇은 VPS(Podman)가 최적의 분업 조합입니다.
