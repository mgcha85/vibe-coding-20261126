Chapter 07. 런칭 · 7.1 사용자 인증의 정석 SNS OAUTH · SUPABASE AUTH · RLS

SNS 로그인 & BaaS 인증 : 왜 Supabase인가?

바이브 코딩 시 "로그인 백엔드 직접 구현"은 최악의 안티패턴입니다. 검증된 BaaS로 5분 만에 OAuth를 붙이고 RLS로 격리합니다.

⚠️ 직접 구현(DIY Auth)의 보안 참사
취약점 덩어리

AI에게 "JWT 로그인 백엔드 짜줘"라고 요청하면 겉만 돌아가는 위험천만한 코드가 생성됩니다.

1. JWT 시크릿 & LocalStorage 탈취 위험 브라우저 LocalStorage에 저장하여 악성 스크립트(XSS) 1초 탈취, 유효기간 만료 예외 누락.
2. Refresh 토큰 로테이션 & 세션 무효화 부재 동시 요청 시 토큰 중복 재발급 레이스 컨디션, 비밀번호 변경 시 기존 세션 강제 만료 미구현.
3. 카카오/구글 OAuth 규격 파편화 제공자마다 제각각인 인증 응답 규격 파싱 및 콜백 핸들링에 수백 줄의 유지보수 부채 발생.
❌ AI가 흔히 만드는 취약 코드 안티패턴: Security Bug
// LocalStorage 저장 ➔ XSS 공격 시 1초 만에 계정 탈취
localStorage.setItem('accessToken', token);
// 하드코딩된 시크릿 키 ➔ 깃허브 공개 레포 노출 대참사
jwt.verify(token, "my-super-secret-123");
❌ 비밀번호 해싱 · 세션 관리에 엔지니어링 40시간 낭비 Anti-Pattern
⚡ 해결책 : Supabase Auth · RLS 직결
월 50,000 MAU 무료

Google, Kakao, GitHub OAuth를 클릭 한 번으로 활성화하고, 프론트엔드와 PostgreSQL RLS를 직결합니다.

STEP 1. 대시보드 클릭 SNS Provider 토글 Google, Kakao Client ID 복붙
STEP 2. 프론트 3줄 호출 원클릭 리다이렉트 PKCE 보안 흐름 & 쿠키 동기화
STEP 3. DB 레벨 격리 RLS 자동 바인딩 auth.uid() = user_id 격리
// 1. 프론트엔드(Svelte/React): 단 4줄로 구글/카카오 로그인 완료
const { data, error } = await supabase.auth.signInWithOAuth({
provider: 'google', // 'kakao', 'github' 전환 즉시 가능
options: { redirectTo: `https://myapp.com/auth/callback` }
});
// 2. PostgreSQL RLS 정책: 백엔드 API 없이도 유저별 데이터 자동 보호
ALTER TABLE profiles ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Users can read own profile" ON profiles
FOR SELECT USING (auth.uid() = id);
🔄 supabase.auth.onAuthStateChange((event, session) => ...)로 실시간 상태 동기화 Zero Polling
✓ 백엔드 API 작성 없이 프론트 ➔ Supabase 다이렉트 쿼리 실현 Zero Auth Codebase
