결제 연동 실전 : Toss Payments & PayPal

국내 간편결제(Toss)와 글로벌 결제(PayPal)의 3단계 승인 아키텍처를 이해하고, 법적 필수 표기사항과 보안 원칙을 준수합니다.

💳 국내 1위 PG : Toss Payments 위젯
카카오·토스·네이버페이 지원
1. 결제 UI 위젯 (Payment Widget SDK) 프론트엔드에 renderPaymentMethods() 한 줄로 모든 카드사 및 간편결제 UI 자동 렌더링.
2. 서버 최종 승인 API (Confirm Flow) 클라이언트가 받은 paymentKey, orderId, amount를 백엔드에서 Toss API에 POST 승인 요청.
// 프론트엔드 결제 요청
await paymentWidget.requestPayment({
orderId: "ORDER_20261126_01", orderName: "PRO 멤버십 1개월",
amount: 29000, successUrl: window.location.origin + "/success"
});

  • • 약관 링크: 이용약관 · 개인정보처리방침 · 환불/취소 정책
  • • 사업자 정보: 상호명, 대표자명, 사업자번호, 통신판매업 신고번호, 주소
✓ 테스트 키로 즉시 연동 후 사업자 등록 시 라이브 키 교체 Domestic Standard
🌐 글로벌 결제 : PayPal · 결제 보안 원칙
전 세계 카드 · USD 수납
1. PayPal Orders API (v2) 흐름 서버에서 주문 생성(createOrder) ➔ 유저 결제 승인 ➔ 서버에서 캡처(captureOrder)로 안전 완료.
// 백엔드 Webhook HMAC 서명 검증 (위조 방지)
const isValid = verifyWebhookSignature({
headerSignature: req.headers['paypal-transmission-sig'],
webhookId: process.env.PAYPAL_WEBHOOK_ID, body: req.rawBody
});
🛡️ 결제 연동 엔지니어링 3대 철칙:
① 카드번호 보관 절대 금지: 카드 정보는 100% PG사 인프라에만 남기며, 내 DB에는 paymentKey만 저장 (PCI-DSS 준수).
② Webhook 시크릿 서명 검증: 위조된 가짜 결제 완료 HTTP 요청을 막기 위해 HMAC 서명 헤더를 반드시 검증.
③ 멱등성(Idempotency) 보장: 네트워크 재시도로 동일 주문이 2번 승인되지 않도록 DB Unique Key(orderId) 잠금.
✓ Webhook 수신 시점에만 DB 결제 상태를 'PAID'로 변경 Zero Leakage
💡 실무 원칙: 결제 완료 처리는 브라우저 프론트엔드가 아닌, PG사 Webhook 비동기 콜백에서 DB 트랜잭션으로 처리해야 유저가 창을 닫아도 안전합니다.
