APPENDIX A.1 · 브라우저 연동 인프라 BROWSER INFRASTRUCTURE · CDP vs. EGO-LITE

AI Agent 브라우저 연결 : Chrome CDP 직접 연결 vs. ego-lite

에이전트에게 실제 웹 상호작용 능력을 부여할 때, 사용자의 일상 브라우징 간섭 없이 세션 격리 · 토큰 최적화 · SSO 인수(Takeover)를 달성하는 전략을 선택해야 합니다.

🌐 방법 1. Chrome / Brave 직접 연결 (CDP Port 9222)
CDP 원격 디버깅
브라우저 백그라운드 원격 디버깅 기동: 
# Brave / Chrome 9222 포트 활성화
nohup brave-browser --remote-debugging-port=9222 --user-data-dir=/tmp/agent-chrome-profile >/dev/null 2>&1 &
# (Google Chrome 실행 시 google-chrome 명령어 사용)
💬 Agent 지시 프롬프트 예시:
"로컬 9222 포트에 실행 중인 Chrome CDP에 연결해서 https://target-service.com에 접속하고, 최신 공지사항 목록을 추출해 줘."
⚠️ 단점: 사용자 개인 탭 간섭 위험, 원본 DOM 그대로 전달되어 토큰 과소비

핵심 비교 : ego-lite vs. Chrome (AI Agent를 위해 왜 ego-lite를 쓰는가?)

4대 아키텍처 차별점
비교 항목 일반 브라우저 (Chrome / Brave CDP 직접 연결) 에이전트 전용 브라우저 (ego-lite & ego-browser)
🛡️ 세션 격리 (Isolation) 사용자의 개인 탭, 쿠키, 검색 기록과 뒤섞이거나 별도 임시 프로필 수동 생성 필요. 에이전트 동작 시 창 포커스를 빼앗겨 작업 방해. 사용자와 AI가 Chromium을 공유하되 에이전트 전용 Space (독립 BrowserContext)에서 작동. 사용자 탭/포커스 침범 0%.
📉 토큰 최적화 (Token Diet) 수만 줄의 원본 HTML DOM 전체를 컨텍스트에 주입하여 페이지당 30,000~80,000 토큰 과소비 & 윈도우 조기 폭발. 접근성 트리(Accessibility Tree) & ARIA Selector 스냅샷으로 상호작용 요소만 압축 추출. 토큰 80~90% 절감.
🤝 인간-AI 인수 (SSO / 2FA) 사내 SSO 로그인, 2단계 인증(OTP), Cloudflare CAPTCHA 차단 시 자동화 스크립트가 먹통이 되며 전체 워크플로우 크래시. 인증이 필요할 때 사용자가 Space 탭에서 직접 2FA/로그인 처리(Takeover). 쿠키가 유지되어 에이전트가 바로 작업 재개.
🔌 에이전트 도구 결합 원격 디버깅 포트 관리, 웹소켓 CDP 클라이언트 스크립트(Playwright/Puppeteer) 작성 등 하네스 구축 공수 과다. MCP(Model Context Protocol) 및 단일 ego-browser CLI 지원으로 Cursor/에이전트에 즉시 네이티브 도구로 결합.
💡 실전 권장 전략: 단순 스크래핑은 CDP 연결로 빠르게 테스트하고, 로그인 포털 자동화 · 대규모 E2E 태스크는 ego-lite Space + MCP 조합을 사용하십시오.
