Chapter 08. 가드레일 · 8.5 소프트웨어 공급망 방어 Lockfile & Hash Verification

공급망 공격 방어: Lockfile 무결성 해시와 패키지 검증 자동화

AI가 "이 패키지를 설치하면 해결됩니다"라고 할 때, 그 패키지가 실제로 존재하는지 악성코드인지 어떻게 확신하십니까?

ARMOR 01. 해시 무결성 SHA-256 고정

Lockfile: 보안 무결성 방패

단순한 버전 기록서가 아닙니다. 모든 패키지의 원본 바이너리 SHA-256 해시를 암호학적으로 고정하여 배포 시 변조를 100% 차단합니다.

# 생태계별 표준 락파일 (Git 커밋 필수)
• Python: uv.lock (초고속 결정론적 빌드)
• Node: pnpm-lock.yaml / package-lock.json
• Rust: Cargo.lock (바이너리 일치 보장)
⚠️ AI의 락파일 임의 삭제/재생성 절대 금지
  • • CI 환경: npm ci 또는 uv sync --frozen 사용.
✓ 락파일이 고정된 상태에서는 중간자 변조 공격(MITM) 무력화
ARMOR 02. 설치 전 검증 Slopsquatting 차단

패키지 메타데이터 사전 스캔

AI가 추천한 패키지를 무작정 설치하기 전에, 공식 레지스트리(npm, PyPI)에서 생성일자와 다운로드 수를 조회하여 환각 공격을 걸러냅니다.

# CLI 사전 조회 검증 스크립트
$ npm view <package> time.created
$ pip index versions <package>
> 등록된 지 30일 미만이거나 다운로드 100회 미만인 패키지는 설치 즉시 중단 경고!
  • • 자가 검증: "유명 라이브러리의 철자 변형인가? 공식 오너인가?" 확인.
⚠️ AI가 만든 유령 패키지는 설치 명령 치는 순간 침투 완료
ARMOR 03. 자동 취약점 감사 Audit Automation

CVE 데이터베이스 자동 매핑

이미 알려진 보안 취약점(CVE)이 포함된 오래된 의존성을 AI가 가져다 쓰는 것을 방지하기 위해 정기 감사를 수행합니다.

# 파이프라인 자동 감사 명령어
$ uv pip check && pip-audit
$ npm audit --audit-level=high
$ cargo audit
> High/Critical 취약점 발견 시 CI Fail
  • • Dependabot: 주 1회 보안 패치 PR 자동 생성 연동.
✓ 과거 취약점이 포함된 레거시 의존성의 프로덕션 유입 방지
🛡️ 공급망 철칙: "새로운 패키지 추가는 '인간의 명시적 승인'을 거치고, 배포는 오직 'Lockfile 무결성 해시'를 통해서만 수행한다."
