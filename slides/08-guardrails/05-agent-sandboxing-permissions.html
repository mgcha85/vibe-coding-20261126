Chapter 08. 가드레일 · 8.4 에이전트 런타임 제어 Sandbox & Permission Gate

에이전트 실행 격리: 샌드박스(Sandbox)와 3단계 권한 게이트

AI 에이전트에게 내 호스트 OS의 루트(Root) 터미널을 열어주는 것은 낯선 외주 개발자에게 집 열쇠를 통째로 건네는 것과 같습니다.

LEVEL 01. 격리 아키텍처 호스트 보호

컨테이너 기반 샌드박스 격리

에이전트가 실행하는 모든 쉘 커맨드는 호스트 PC가 아니라 도커(Docker) 컨테이너 또는 마이크로VM 내부에서만 돌도록 가둡니다.

# 격리 샌드박스 실행 제약 3대 원칙
1. 파일 마운트: 현재 작업 디렉토리만 마운트
2. 네트워크 제한: 로컬 사내 인트라넷 차단
3. Non-root 유저: sudo 권한 원천 박탈
  • • 효과: AI가 실수로 rm -rf /를 쳐도 샌드박스 컨테이너만 죽고 호스트는 100% 안전.
✓ 내 맥북/PC의 홈 디렉토리(~/.ssh, 키체인) 접근 원천 봉쇄
LEVEL 02. 명령어 3단계 분류 권한 등급제

안전 / 민감 / 파괴적 커맨드 통제

모든 명령을 일괄 허용하거나 일괄 차단하지 않고, 위험도에 따라 3단계로 차등 제어하여 개발 속도와 안전의 균형을 잡습니다.

🟢 Safe (자동 승인) ls, git status, cargo check
🟡 Sensitive (네트워크) curl, uv pip install, git fetch
🔴 Destructive (결재) rm, drop, kill, git push --force
  • • Human-in-the-Loop: 빨간색 등급은 인간의 명시적 클릭(승인) 없이는 실행 중단.
✓ 일상적 조회는 0초 통과, 치명적 변경은 브레이크 작동
LEVEL 03. 룰셋 주입 AGENTS.md 규칙

에이전트 행동 지침(Guardrail Rules)

에이전트의 뇌(LLM)에 프로젝트 착수 전부터 "절대 하지 말아야 할 행위"를 불변의 시스템 규칙으로 못 박아둡니다.

# AGENTS.md / .cursorrules 보안 규칙
- NEVER edit .env files directly.
- NEVER run git push with --force.
- ASK before adding external dependencies.
- ALWAYS verify DB migration with RLS.
  • • 컨텍스트 고정: 모델이 딴짓을 하려 할 때마다 룰이 강력한 억제력 발휘.
✓ 프롬프트 단계(뇌)와 런타임 단계(손)의 2중 통제선 구축
🛡️ 권한의 대원칙: "에이전트에게 필요한 것은 '무제한 권한'이 아니라 '작업 목적에 꼭 맞는 최소 권한(Least Privilege)'뿐이다."
