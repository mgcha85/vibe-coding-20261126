Chapter 08. 가드레일 · 8.7 실전 5분 실습 Hands-on Security Setup

내 프로젝트에 4대 보안 가드레일 즉시 이식하기

오늘 개발 중인 프로젝트에 아래 3단계 설정을 적용하면, AI와의 협업 중 발생할 수 있는 보안 사고의 99%를 원천 차단합니다.

STEP 01. 커밋 방패 Gitleaks 1분 세팅

Pre-commit 훅 즉시 활성화

시크릿이 담긴 코드가 로컬에서 Git 커밋되는 순간을 물리적으로 거절하는 훅을 설치합니다.

# 1. pre-commit 도구 설치
uv add --dev pre-commit
# 2. .pre-commit-config.yaml 생성
cat << 'EOF' > .pre-commit-config.yaml
repos:
  - repo: https://github.com/gitleaks/gitleaks
    rev: v8.18.2
    hooks: [{ id: gitleaks }]
EOF
# 3. 훅 등록
uv run pre-commit install
✓ 이후 모든 git commit 시 자동 시크릿 검사 수행
STEP 02. DB 불변 템플릿 RLS 표준 DDL

테이블 DDL 표준 스니펫 주입

새 테이블을 생성할 때 AI에게 무조건 포함시키도록 요구하는 불변의 SQL 골격입니다.

-- AI에게 테이블 생성 시 강제할 템플릿
CREATE TABLE user_items (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid REFERENCES auth.users NOT NULL,
  payload jsonb DEFAULT '{}'::jsonb
);
ALTER TABLE user_items ENABLE ROW LEVEL SECURITY;
CREATE POLICY "User items isolation" ON user_items
  FOR ALL USING (auth.uid() = user_id)
  WITH CHECK (auth.uid() = user_id);
✓ 유저 간 데이터 침범 100% 원천 봉쇄
STEP 03. 에이전트 헌법 AGENTS.md 규칙

보안 룰셋(Security Rules) 못 박기

프로젝트 루트의 AGENTS.md에 아래 보안 조항을 추가하여 AI의 탈선을 방지합니다.

## Security Rules (MANDATORY)
1. NEVER output or log secrets (.env).
2. NEVER execute 'rm -rf' or destructive shell.
3. NEVER add unverified dependencies; check registry first.
4. ALWAYS use parameterized queries & RLS policies.
5. ALWAYS run 'uv sync --frozen' or locked installs.
✓ 에이전트가 코드를 짜기 전 매 턴마다 강제 상기
🛡️ 5분 적용 결과: 개발자의 추가 코딩 없이, 설정 파일 3개만으로 프로덕션 엔터프라이즈급 보안 가드레일 완성.
