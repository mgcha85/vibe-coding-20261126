2.4 이상과 현실 (Reality Check) : ① 자연어의 한계 vs ② BaaS 레고 블록 전략

단일 파일 토이 데모를 넘어, 실제 유저와 트랜잭션이 붙는 순간 발생하는 소프트웨어 복잡계의 벽과 생존 전략:

쟁점 ① COMPLEXITY WALL 자연어의 한계

'말만 하면 된다'는 환상 vs 복잡계의 벽

세션 장기화에 따른 기억력 붕괴 (Context Drift) 파일 20개+ 위험 구간
🚨 상태·네트워크 복잡계: 1개 파일 토이는 작동하지만, 실제 유저 상태 동기화, 트랜잭션 롤백, 네트워크 재시도 앞에서는 자연어 프롬프트만으로 통제 불가.
🚨 컨텍스트 오염 (Drift): 세션이 길어지면 앞선 아키텍처 결정을 망각하고 기존 코드를 덮어써 버리는 치명적 퇴행 발생.
"자연어는 모호성을 허용하지만, 컴퓨터 런타임은 단 1비트의 모호성도 용납하지 않는다."
쟁점 ② ARCHITECTURE STRATEGY 현실적 해법

바닥부터 구축 vs 현대 BaaS 레고 블록 조립

모던 BaaS 레고 블록 조립 (Glue Code 아키텍처) 검증된 표준 모듈
⚠️ 바닥부터 짜면 파탄: AI에게 DB 커넥션 풀링, 세션 핸들러, 웹훅을 바닥부터 코딩시키면 보안 취약점과 병목이 폭발합니다.
✅ 글루 코드(Glue Code) 전략: 이미 수만 개 기업에서 검증된 BaaS 모듈을 레고처럼 조립하고, 에이전트는 결합 로직만 작성합니다.
"바닥부터 만들지 말고, 검증된 블록을 조립하라" Chapter 03 런칭 편 상세 ➔
📌 Takeaway: 프롬프트는 '모든 것을 짓는 요술봉'이 아니라, '검증된 컴포넌트를 조립하는 접착제(Glue)'로 사용할 때 비로소 작동합니다.
