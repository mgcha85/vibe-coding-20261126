Chapter 05. 병렬화 · 5.2 물리 격리 인프라 PHYSICAL ISOLATION · ZERO DISK OVERHEAD

격리 기술의 핵심 : git worktree vs 기존 브랜치 전환

하나의 레포지토리에서 여러 브랜치를 서로 다른 물리 디렉터리로 동시 체크아웃하여 에이전트 간 간섭(Race Condition)을 0%로 박멸합니다.

❌ 왜 git checkout/switch로는 불가능한가? Collision Alert

동일한 로컬 작업 폴더에서 2개 이상의 에이전트를 돌리면 발생하는 참사:

1. 파일 쓰기 충돌 (File Clobbering)
에이전트 A가 고치는 파일 위에 에이전트 B가 중간 코드를 덮어써서 파괴.
2. 락 파일 & 빌드 캐시 오염
node_modules, target/, .git/index.lock 충돌로 빌드 즉각 크래시.
3. 개발자 락아웃 (Developer Lockout)
에이전트가 2분간 수정 중일 때 다른 브랜치로 switch조차 못 하고 손 묶임.
➔ 해결책: 디스크 용량 낭비 없이 물리 폴더만 N개로 쪼개는 git worktree
⚡ git worktree 동작 원리와 3대 워크스페이스 Shared .git Database
# 메인 저장소에서 단 1초 만에 격리 작업실 생성:
git worktree add ../wt-auth -b feat/auth-service
git worktree add ../wt-billing -b feat/billing-stripe
git worktree add ../wt-e2e -b test/e2e-pipeline
✓ 디스크 용량 90% 절약 (.git 중복 클론 없음)
✓ 완전한 파일 격리 ➔ Cursor/VSCode N개 창 동시 실행
🌿 Git Worktree의 미학: 중복 클론 없이 완벽히 격리된 물리 디렉토리를 에이전트마다 배정하십시오.
