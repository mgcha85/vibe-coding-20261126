Chapter 06. 비용 · 6.5 코드 아키텍처 다이어트 ATOMIC MODULARIZATION · 200-LINE RULE

아키텍처 단위 토큰 다이어트 : 소스트리 표준화 & 원자적 함수 분할

하나의 파일에 1,500줄을 몰아넣지 마십시오. 200줄 이하 원자적 파일 분할과 30줄 순수 함수 표준화로 Diff 편집 토큰을 90% 절감합니다.

💀 2,000줄 모놀리식 파일의 비극
Anti-Pattern

한 파일에 1,500~2,000줄 코드를 몰아넣으면, 코드 5줄 고치려고 2,000줄 전체를 읽고 diff를 생성해야 합니다.

📁 auth_monolith.go (1,850줄)
├─ 토큰 발급 (200줄)
├─ 비밀번호 해싱 & 검증 (300줄)
├─ HTTP 요청 핸들러 12개 (600줄)
└─ SQL 쿼리 & 트랜잭션 (750줄)
🚨 오타 1줄 수정 = 20,000 토큰 증발 + 줄번호 착오 오류 폭증
⚠️ Edit Conflict & 린트 악순환: 파일이 길수록 AI가 변경 대상을 잘못 찾아 코드를 덮어쓰거나, 린트 오류를 잡으려다 다른 부분을 망가뜨리는 퇴행(Regression) 유발.
✓ 500줄 초과 파일: AI 코딩의 적 Refactor Now
✂️ 소스트리 표준화 & 200줄 원자 분할 규칙
95% Token Saved
1. 파일당 200줄 이하 엄수 Single Responsibility
📄 auth/jwt.go (80줄) · 토큰 전담
📄 auth/handler.go (110줄) · 라우팅
📄 auth/repository.go (90줄) · DB
✓ 수정 시 해당 파일 80줄만 로드 → 토큰 95% 절감!
2. 함수당 30줄 이하 순수화 Pure Function
• 1개 함수는 1가지 책임만 수행
• 입출력이 명확한 결정론적 구조
• 단위 테스트 작성이 극도로 용이
✓ AI의 코드 치환 성공률 100% 보장
❌ 모놀리식 파일 수정: 2,000줄 로드 + diff 연산 = 15,000 토큰
⚡ 원자적 파일 수정: 80줄 로드 + 10줄 diff = 600 토큰 (96% 절감)
💡 아키텍처가 곧 토큰이다: 코드를 잘게 쪼개는 것은 클린 코드일 뿐 아니라, AI API 요금을 1/20로 줄이는 최고의 경제학입니다. Clean Code = Cheap Code
✂️ 원자적 아키텍처의 위력: 파일을 200줄 이하로 쪼개는 순간, 에이전트의 변경 오차는 0이 되고 입출력 토큰은 기하급수적으로 줄어듭니다.
