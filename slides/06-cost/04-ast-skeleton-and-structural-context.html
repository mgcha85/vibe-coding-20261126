Chapter 06. 비용 · 6.3 구조적 컨텍스트 엔지니어링 AST SKELETON · TREE-SITTER · AST-GREP

구문 기반 컨텍스트 압축 : AST 구조 & Tree-sitter 스켈레톤

파일 전체(2,000줄)를 무식하게 읽히지 마십시오. AST(추상 구문 트리)로 함수 시그니처와 인터페이스만 추출하여 토큰을 98% 압축(10k ➔ 200 토큰)합니다.

🌳 AST (추상 구문 트리) 구조의 본질
Syntax Tree

소스코드를 단순 텍스트 줄(Line)이 아닌, 문법 계층(Class ➔ Method ➔ Params ➔ Body)의 트리 구조로 파싱하여 필요한 노드만 정밀 추출합니다.

📁 Program (SourceFile)
└─ 📦 ClassDeclaration: OrderService
├─ 🏷️ MethodSignature: createOrder(...) [주입!]
└─ 🚫 BlockBody { 150줄 내부 DB쿼리 } [생략!]
└─ 🏷️ MethodSignature: cancelOrder(...) [주입!]
1. Tree-sitter: 에러가 있거나 미완성된 코드도 깨지지 않고 증분 파싱(Incremental Parsing)하는 고속 구문 엔진.
2. ast-grep (sg 스킬): 정규식 대신 sg -p 'fn $NAME($$$ARGS)' 패턴으로 함수 선언만 0초 만에 추출하는 에이전트 스킬.
✓ 내부 구현체 제거: -98% 토큰 압축 Attention Focus
🦴 Skeleton Folding : 10,000 토큰 ➔ 200 토큰 압축
98% Token Saved
❌ Naive Raw Code (2,000줄) 10k Tokens
// 100줄의 import 및 내부 상태

    await db.raw('SELECT...');

      if (item.price < 0) ...
    }
    // 수백 줄의 트랜잭션 롤백 로직

}
⚠️ AI가 구현 세부사항에 질식하여 Attention 희석

// AST로 추출된 공개 인터페이스 계약
export interface OrderService {

  getStatus(orderId: string): Promise<Status>;
}
✓ AI는 메소드 명과 타입만 보고 100% 무오차 연동 구현!
🛠️ 실전 ast-grep 에이전트 스킬 활용 예시:
$ sg scan -p 'export function $NAME($$$ARGS): $TYPE { $$$ }' --json | jq '.[].signature'
