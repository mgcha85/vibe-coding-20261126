ROOT CAUSES OF FAILURE 모놀리식의 한계

왜 실전 소프트웨어 개발에 실패했는가?

단일 LLM 컨텍스트에 모든 역할을 몰아넣은 Monolithic 구조의 치명적 한계 3가지:

⚠️ 컨텍스트 드리프트 (Context Drift & Goal Loss)

수십 턴 동안 터미널 에러 로그와 파일 덤프가 쌓이면서, 최초 유저가 지시했던 원래 목표(Original Goal)를 완전히 망각하고 표류.

⚠️ 연쇄 환각 (Cascading Hallucination) & 무한 루프

자신이 상상한 가짜 파일 경로를 사실로 믿고, 이를 고치려다 엉뚱한 폴더를 무한 생성·삭제하며 크레딧과 컨텍스트만 전소.

⚠️ 벤치마크 점수 참패 (SWE-bench < 2%)

복잡한 실전 리포지토리 태스크 성공률이 1.96%에 그치며, 단일 루프로는 상용 프로덕션 투입이 불가능함을 입증.

“단일 LLM에게 모든 것을 다 시키는 모놀리식 루프는 필연적으로 붕괴한다.”

1. Pydantic : 입출력 계약 강제 Fail-Fast

AI의 빈번한 실수인 None 역참조, 잘못된 속성 접근을 런타임 전 0.1초 만에 적발.

3. import-linter : 아키텍처 계층 수호 No Spaghetti

도메인/모델이 UI나 컨트롤러를 역참조하는 순환 수렁 차단. contracts = "ui ➔ service ➔ domain" 단방향 강제.

4. Ruff : 초고속 정적 구문 세척 Rust Fast

AI가 남발하는 미사용 import, 포매팅 결함, 위험 구문을 0.01초 만에 자동 교정(ruff check --fix).

5. Pytest : 피드백 자가치유 루프 Self-Healing

테스트 실패 로그를 본 에이전트가 코드를 스스로 수정하여 100% All-Green까지 자율 수렴.

에이전트 런타임(Claude Code, Antigravity 등)은 매 턴마다 분산된 자산들을 '단 하나의 Context Window'로 합성하여 전송합니다.

## 1. Hybrid Score Formulation
Score(d, q, t) = α · CosineSim(E_q, E_d) + (1-α) · Quality(d) · exp(-λ · Δt)
• α = 0.65 : 벡터 임베딩 유사도 반영 가중치
• λ = 0.048 : 반감기 14.4시간 기준 시간 감쇠 계수 (Time-decay factor)
• Δt : 현재 시각과 문서 생성 시각의 차이 (단위: Hours)
## 2. Latency Budget & SLA Contract

Rules 체계와 Grill-me : 맹종을 넘어선 능동적 정렬

사용자의 모호한 지시를 그대로 코딩하면 90% 확률로 엉뚱한 결과가 나옵니다. 계층형 Rules로 제약을 걸고, /grill-me로 에이전트가 역질문하게 만들어야 합니다.

🛡️ Rules 체계의 동작 원리 Hierarchical Precedence

스킬이 "어떻게 작업할 것인가(How)"라면, 룰은 "무엇을 절대 넘지 말아야 하는가(Constraint)"입니다.

1️⃣ Global Rules (~/.gemini/config, ~/.cursorrules)
개인 개발 환경 기본값: "모든 프로젝트에서 답변은 한국어, 불필요한 사과 금지"
2️⃣ Project Rules (.cursor/rules/*.md, .agents/rules/)
레포지토리 공통 규칙: "BE는 Python 3.12 + DuckDB, FE는 Astro 5, pandas 금지"
3️⃣ Directory Rules (Local AGENTS.md / GEMINI.md)
특정 폴더 우선순위: data/raw/ 원본 h5ad 수정 절대 금지, backend/ 내 import pandas 전면 금지.
💡 트리거 방식: always_on(무조건 주입)과 특정 파일 수정 시만 활성화되는 glob_trigger로 토큰 최적화.
🔥 /grill-me : 에이전트의 역질문 인터뷰
Anti-Yes-Man Mode

바이브 코딩의 가장 큰 위험은 에이전트가 인간의 불완전한 프롬프트에 "네, 알겠습니다!"라며 섣불리 코드를 500줄 짜버리는 '예스맨 증후군(Yes-Man Syndrome)'입니다.

❌ 무지성 즉시 코딩 (Yes-Man)
• "PBMC 군집 분석 파이프라인 만들어줘"
➔ 에이전트: "네!" (pandas와 matplotlib로 500줄 작성)

Lifecycle Hooks : 인간의 눈을 대신하는 자동 검증기

에이전트가 도구를 호출하거나 실행을 종료할 때, 백그라운드에서 쉘 스크립트를 가로채 실행하는 이벤트 주도형 하네스(Hook)입니다.

🔄 에이전트 루프와 Hook 트리거 시점 Execution Interception
① PreInvocation 모델 호출 전
프롬프트 주입 전 동적 환경변수나 최신 Git 상태를 검사하여 컨텍스트에 추가.
② PreToolUse (안전 차단기) CRITICAL
rm -rf, git push --force, DB 드롭 같은 파괴적 커맨드 감지 시 도구 실행 즉시 차단!
③ PostToolUse (자동 린터/포매터) AUTOMATION
에이전트가 코드를 쓰자마자 ruff format이나 prettier를 백그라운드 실행하여 코드 스타일 일관성 보장.
④ Stop Hook (작업 완료 게이트) QUALITY GATE
에이전트가 "끝났습니다"라고 종료하려 할 때, 단위 테스트를 돌려 실패하면 종료를 거부하고 자가 치유 루프로 되돌림.
💡 장점: 에이전트에게 잔소리할 필요 없이, 시스템 스크립트가 물리적으로 코드 품질을 강제합니다.
⚙️ hooks.json 실전 구성 방법 .agents/hooks.json

루트 또는 .agents/hooks.json에 이벤트 핸들러를 정의하면 에이전트 프레임워크가 런타임에 이를 자동 감지하여 인터셉트합니다.

{
"safety-gate": {
"PreToolUse": [
{
"matcher": "run_command",
"hooks": [{ "command": "./scripts/check_dangerous_cmd.sh" }]
}
]
},
"auto-linter": {
"PostToolUse": [
{
"matcher": "replace_file_content",
"hooks": [{ "command": "uv run ruff check --fix" }]
}
]
}
}

바이브 코딩의 생산성 격차는 프롬프트 작문 실력이 아니라 "에이전트 병렬화 지수(Parallel Index)"에서 갈립니다.

⏳ 동기식 개발의 함정 (The Synchronous Bottleneck)
1x Bottleneck

1개의 대화창에서 AI가 타이핑하는 글자를 멍하니 지켜보는 것은 바이브 코딩에서 가장 치명적인 안티패턴입니다.

🚀 비동기 오케스트레이터 (Async Human)
Nx Scaling

개발자는 직접 삽질하는 일꾼이 아니라, 여러 명의 AI 주니어에게 태스크를 동시 분배하고 취합하는 매니저(PM · Architect)입니다.

🎯 태스크 병렬 분할 (Fire & Forget)
인증 모듈, 결제 연동, DB 마이그레이션, E2E 테스트를 4개 독립 트랙으로 쪼개어 동시 투척.
⚡ 추론 레이턴시 완전 은폐 (Latency Hiding)
에이전트 A가 코드를 짜는 2분 동안, 인간은 에이전트 B의 요구사항을 지시하고 에이전트 C의 PR을 리뷰.
📊 단일 인간 ➔ 4인 개발팀 산출물
완벽한 격리 인프라 위에서 3~5개의 작업이 병렬 완료되어 1시간 만에 4개 기능 동시 런칭.

Chapter 05. 병렬화 · 5.2 물리 격리 인프라 PHYSICAL ISOLATION · ZERO DISK OVERHEAD

격리 기술의 핵심 : git worktree vs 기존 브랜치 전환

하나의 레포지토리에서 여러 브랜치를 서로 다른 물리 디렉터리로 동시 체크아웃하여 에이전트 간 간섭(Race Condition)을 0%로 박멸합니다.

❌ 왜 git checkout/switch로는 불가능한가? Collision Alert

동일한 로컬 작업 폴더에서 2개 이상의 에이전트를 돌리면 발생하는 참사:

1. 파일 쓰기 충돌 (File Clobbering)
에이전트 A가 고치는 파일 위에 에이전트 B가 중간 코드를 덮어써서 파괴.
2. 락 파일 & 빌드 캐시 오염
node_modules, target/, .git/index.lock 충돌로 빌드 즉각 크래시.

사람의 실수 차단
⚠️ 로컬 수동 배포(FTP/SSH 직접 복사)의 위험 빌드 산출물 누락, 로컬 환경 의존성 오염, 배포 중 서버 다운타임, 시크릿 키 유출 위험 상존.

🚀 CD (지속적 배포 - Continuous Deployment) CI 검증이 통과된 클린 코드만 운영 서버(Cloud Run, VM, Vercel)에 무중단 자동 릴리즈.

Chapter 08. 가드레일 · 8.2 데이터베이스 권한 격리 PostgreSQL / Supabase RLS

RLS(Row Level Security) 누수 방지: 3대 치명적 함정과 방어 DDL

BaaS 환경에서는 프론트엔드가 DB에 직접 쿼리를 날립니다. 백엔드 방화벽이 없으므로 DB 자체에 방패를 씌워야 합니다.

PITFALL 01. 비활성화 기본값 기본 공개 위험

ENABLE RLS 누락의 참사

PostgreSQL은 테이블 생성 시 RLS가 기본적으로 OFF 상태입니다. AI에게 그냥 테이블을 만들라고 하면 누락되어 anon 키로 전 고객 데이터 조회가 열립니다.

-- ❌ AI가 흔히 짜는 취약한 SQL
CREATE TABLE profiles ( id uuid, ... );
-- ✅ 필수 1줄: RLS 강제 활성화
ALTER TABLE profiles ENABLE ROW LEVEL SECURITY;
  • • 결과: RLS 활성화 없이는 아무리 복잡한 정책을 써도 0% 적용.
  • • 규칙: 모든 DDL 마이그레이션 끝에 ENABLE RLS 필수 강제.
⚠️ RLS 누락 시 브라우저 콘솔에서 전체 DB 덤프 가능
PITFALL 02. 반쪽짜리 정책 CRUD 누락

SELECT만 막고 UPDATE 방치

AI는 종종 FOR SELECT 정책만 달랑 작성합니다. 이 경우 인증된 사용자가 타인의 결제 금액이나 상태를 UPDATE 해버리는 권한 상승 버그가 발생합니다.

-- ❌ 타인 프로필 변조 가능 구멍
CREATE POLICY p1 ON users FOR SELECT...
-- ✅ CRUD 전체 격리 (INSERT, UPDATE, DELETE)
CREATE POLICY p_all ON orders FOR ALL
USING (auth.uid() = user_id)
WITH CHECK (auth.uid() = user_id);
  • • USING vs CHECK: 읽기/삭제 조건(USING)과 쓰기/수정 조건(WITH CHECK) 동시 검증.
⚠️ FOR ALL 정책으로 4대 작업(CRUD) 완전 격리 필수

에이전트 실행 격리: 샌드박스(Sandbox)와 3단계 권한 게이트

AI 에이전트에게 내 호스트 OS의 루트(Root) 터미널을 열어주는 것은 낯선 외주 개발자에게 집 열쇠를 통째로 건네는 것과 같습니다.

# 격리 샌드박스 실행 제약 3대 원칙
1. 파일 마운트: 현재 작업 디렉토리만 마운트
2. 네트워크 제한: 로컬 사내 인트라넷 차단
3. Non-root 유저: sudo 권한 원천 박탈
  • • 효과: AI가 실수로 rm -rf /를 쳐도 샌드박스 컨테이너만 죽고 호스트는 100% 안전.
✓ 내 맥북/PC의 홈 디렉토리(~/.ssh, 키체인) 접근 원천 봉쇄
LEVEL 02. 명령어 3단계 분류 권한 등급제

안전 / 민감 / 파괴적 커맨드 통제

모든 명령을 일괄 허용하거나 일괄 차단하지 않고, 위험도에 따라 3단계로 차등 제어하여 개발 속도와 안전의 균형을 잡습니다.

🟢 Safe (자동 승인) ls, git status, cargo check
🟡 Sensitive (네트워크) curl, uv pip install, git fetch
🔴 Destructive (결재) rm, drop, kill, git push --force
  • • Human-in-the-Loop: 빨간색 등급은 인간의 명시적 클릭(승인) 없이는 실행 중단.
✓ 일상적 조회는 0초 통과, 치명적 변경은 브레이크 작동
LEVEL 03. 룰셋 주입 AGENTS.md 규칙

에이전트 행동 지침(Guardrail Rules)

에이전트의 뇌(LLM)에 프로젝트 착수 전부터 "절대 하지 말아야 할 행위"를 불변의 시스템 규칙으로 못 박아둡니다.

# AGENTS.md / .cursorrules 보안 규칙
- NEVER edit .env files directly.
- NEVER run git push with --force.
- ASK before adding external dependencies.
- ALWAYS verify DB migration with RLS.
  • • 컨텍스트 고정: 모델이 딴짓을 하려 할 때마다 룰이 강력한 억제력 발휘.
✓ 프롬프트 단계(뇌)와 런타임 단계(손)의 2중 통제선 구축
🛡️ 권한의 대원칙: "에이전트에게 필요한 것은 '무제한 권한'이 아니라 '작업 목적에 꼭 맞는 최소 권한(Least Privilege)'뿐이다."
