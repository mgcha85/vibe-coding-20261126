Chapter 04. 툴체인 · 4.4 Rules & Grill-me GUARDRAILS · INTERACTIVE ALIGNMENT

Rules 체계와 Grill-me : 맹종을 넘어선 능동적 정렬

사용자의 모호한 지시를 그대로 코딩하면 90% 확률로 엉뚱한 결과가 나옵니다. 계층형 Rules로 제약을 걸고, /grill-me로 에이전트가 역질문하게 만들어야 합니다.

🛡️ Rules 체계의 동작 원리 Hierarchical Precedence

스킬이 "어떻게 작업할 것인가(How)"라면, 룰은 "무엇을 절대 넘지 말아야 하는가(Constraint)"입니다.

1️⃣ Global Rules (~/.gemini/config, ~/.cursorrules)
개인 개발 환경 기본값: "모든 프로젝트에서 답변은 한국어, 불필요한 사과 금지"
2️⃣ Project Rules (.cursor/rules/*.md, .agents/rules/)
레포지토리 공통 규칙: "중요 정보는 .env 사용, 프론트엔드는 Svelte, 백엔드는 Go"
3️⃣ Directory Rules (Local AGENTS.md / GEMINI.md)
특정 폴더 우선순위: live-trading/ 내에서는 절대 백테스트 코드 수정 금지.
💡 트리거 방식: always_on(무조건 주입)과 특정 파일 수정 시만 활성화되는 glob_trigger로 토큰 최적화.
🔥 /grill-me : 에이전트의 역질문 인터뷰
Anti-Yes-Man Mode

바이브 코딩의 가장 큰 위험은 에이전트가 인간의 불완전한 프롬프트에 "네, 알겠습니다!"라며 섣불리 코드를 500줄 짜버리는 '예스맨 증후군(Yes-Man Syndrome)'입니다.

❌ 무지성 즉시 코딩 (Yes-Man)
• "유저 인증 기능 만들어줘"
➔ 에이전트: "네!" (NextAuth 혼자 설치)
• 2시간 뒤: "Supabase 쓰기로 했는데 왜 마음대로 라이브러리를 바꿔?" ➔ 전면 롤백
✅ /grill-me 역질문 정렬
• "유저 인증 기능 만들려고 해. /grill-me"
➔ 에이전트: "인터뷰를 시작합니다. 1) JWT vs Session? 2) 소셜 로그인 포함? 3) RLS 정책은?"
• 3분 만에 아키텍처 의사결정 완료 ➔ 원샷 성공
⚙️ 세팅 방법 (AGENTS.md 또는 .cursorrules):
Rule: "설계 결정을 내리기 전 모호한 점이 있다면 즉시 ask_question 도구로 역질문할 것."
Slash Command: /grill-me 호출 시 기획 인터뷰 모드로 진입하여 3~5개 엣지 케이스 확인.
🎯 핵심 테이크어웨이: "훌륭한 에이전트는 코드를 빨리 치는 에이전트가 아니라, 질문으로 설계를 먼저 맞추는 에이전트다."
🛡️ Rules & Grill-me: 에이전트에게 엄격한 제약(Rules)을 씌우고, 역질문(/grill-me)을 유도하여 기획 드리프트를 원천 차단하십시오.

Lifecycle Hooks : 인간의 눈을 대신하는 자동 검증기

에이전트가 도구를 호출하거나 실행을 종료할 때, 백그라운드에서 쉘 스크립트를 가로채 실행하는 이벤트 주도형 하네스(Hook)입니다.

🔄 에이전트 루프와 Hook 트리거 시점 Execution Interception
① PreInvocation 모델 호출 전
프롬프트 주입 전 동적 환경변수나 최신 Git 상태를 검사하여 컨텍스트에 추가.
② PreToolUse (안전 차단기) CRITICAL
rm -rf, git push --force, DB 드롭 같은 파괴적 커맨드 감지 시 도구 실행 즉시 차단!
③ PostToolUse (자동 린터/포매터) AUTOMATION
에이전트가 코드를 쓰자마자 ruff format이나 prettier를 백그라운드 실행하여 코드 스타일 일관성 보장.
④ Stop Hook (작업 완료 게이트) QUALITY GATE
에이전트가 "끝났습니다"라고 종료하려 할 때, 단위 테스트를 돌려 실패하면 종료를 거부하고 자가 치유 루프로 되돌림.
💡 장점: 에이전트에게 잔소리할 필요 없이, 시스템 스크립트가 물리적으로 코드 품질을 강제합니다.
⚙️ hooks.json 실전 구성 방법 .agents/hooks.json

루트 또는 .agents/hooks.json에 이벤트 핸들러를 정의하면 에이전트 프레임워크가 런타임에 이를 자동 감지하여 인터셉트합니다.

{
"safety-gate": {
"PreToolUse": [
{
"matcher": "run_command",
"hooks": [{ "command": "./scripts/check_dangerous_cmd.sh" }]
}
]
},
"auto-linter": {
"PostToolUse": [
{
"matcher": "replace_file_content",
"hooks": [{ "command": "uv run ruff check --fix" }]
}
]
}
}
🛡️ 원천 차단
치명적 명령어 사전 차단
⚡ 자동 포매팅
작업 즉시 린터 자동 적용
🛑 퇴근 불가 게이트
테스트 미통과 시 종료 반려
✓ 결론: "인간이 코드를 일일이 감시하지 않아도 시스템이 안전망을 지킨다"
🪝 Lifecycle Hooks: PreToolUse로 파괴적 명령을 막고, PostToolUse로 린터를 돌리며, Stop Hook으로 품질을 보증하십시오.

Git Worktree : 에이전트별 독립된 물리 작업실

레포지토리를 여러 번 복제하지 않고, 단일 .git 데이터베이스를 공유하며 여러 디렉토리를 동시에 여는 기법입니다.

WORKTREE ORCHESTRATION 컨텍스트 오염 0%

단일 디렉토리에서 여러 에이전트가 동시에 파일을 수정하면 '파일 충돌(Git Lock / File Write Conflict)'과 '프롬프트 컨텍스트 오염'이 발생합니다. Worktree는 이를 물리적으로 완벽 차단합니다.

✓ 1개의 Git 레포로 3개 이상의 IDE 창을 띄워 각각 다른 AI 에이전트 가동
WHY WORKTREE?

복제(Clone) vs Worktree 비교

❌ git clone 3번 하기
• 디스크 용량 3배 낭비 (수 GB 복제)
• 커밋/푸시를 따로 하고 remote를 통해 머지해야 함
• 세팅 시간 5~10분 소요
✅ git worktree 1초 생성
• 디스크 추가 0바이트 (히스토리 공유)
• 메인 레포에서 git merge 즉시 가능
• 명령어 1줄로 0.5초 만에 작업실 생성/삭제
💡 AGENTS.md에 "worktree에서 작업하라"고 명시해두면 에이전트가 격리된 공간에서만 안전하게 작업합니다.
💡 지휘자의 사고방식: 에이전트를 한 명만 부리는 사람은 '코더'이고, 워크트리로 3명을 동시에 부리는 사람은 '팀장'입니다.
